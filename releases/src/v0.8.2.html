Commit only inside a git repository

Tickets, smoke tests and the helper-tool setup work on a plain folder of two clones — and never run git init or stage into a repo that does not own the files.

One rule, checked before the first commit

git rev-parse --show-toplevelrun in the directory the files live in
→
is a repositorycommit its own files there
→
is notno commit — files stay on disk, reported once

A folder with two plain clones

my-app/ not a git repository ├── backend/ git repo → commits here ├── frontend/ git repo → commits here ├── tickets/booking-cancel/ on disk, not committed └── .mcp.json · CLAUDE.md · AGENTS.md · .agents/ commits backend@4f2d9e1 · frontend@6f38a51 parent — none, not a git repository

The same folder after git init

my-app/ git repo → its own files ├── backend/ left to its own repository ├── frontend/ left to its own repository ├── tickets/booking-cancel/ committed in my-app └── .mcp.json · CLAUDE.md · … backend/ and frontend/ are staged into the parent only when .gitmodules registers them as submodules

Never git init

No skill creates a repository for you, and none puts the parent's files into backend/ or frontend/.

Skipping is not failing

A skipped commit never blocks a step. A Committed — <sha> box reads n/a — not a git repository.
